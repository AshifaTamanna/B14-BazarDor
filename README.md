# বাজার দর — BazarDor

বাজার দর is a responsive Bengali-first market-price guide for essential groceries in Bangladesh. Browse today's prices and market trends, compare local bazar prices, and keep track of changes in one place.

## Technologies

- Next.js App Router and React
- TypeScript
- Tailwind CSS 4 with custom responsive styling
- Better Auth with local SQLite or MongoDB, email/password, Google, and GitHub providers
- Live product and category data from the BazarDor API
- Lucide icons and react-hot-toast

## Features

1. Bengali price ticker, date, categories, and mobile-friendly navigation.
2. Live price-rise and price-fall highlights with Bengali numerals.
3. Responsive product cards and category pages with numeric price sorting.
4. Protected product details with market-by-market minimum, maximum, and average prices.
5. Email/password registration and login, with optional Google and GitHub OAuth.
6. Successful registration returns users to sign-in; successful sign-in opens the market dashboard.
7. Profile page and name update form.
8. Loading skeletons, clear error states, and friendly 404 pages.
9. A saved market-data snapshot keeps the catalog available during upstream API outages and labels those prices as saved rather than live.

## Authentication and OAuth setup

Email/password authentication uses Better Auth with local SQLite by default. Set
`BETTER_AUTH_SECRET` to a private random secret of at least 32 characters and
`BETTER_AUTH_URL` to the app's canonical origin (for local development,
`http://localhost:3000`). The URL must not include `/api/auth`.

To enable social sign-in, create OAuth credentials and add these server-only
variables to `.env.local`:

- `BETTER_AUTH_GOOGLE_CLIENT_ID`
- `BETTER_AUTH_GOOGLE_SECRET`
- `GITHUB_CLIENT_ID`
- `GITHUB_CLIENT_SECRET`

The OAuth callback URLs are generated by Better Auth at:

- Google: `http://localhost:3000/api/auth/callback/google`
- GitHub: `http://localhost:3000/api/auth/callback/github`

For Google, create a Web application OAuth client in Google Cloud Console,
configure the OAuth consent screen, and add the local app origin as an
authorized JavaScript origin and the Google callback above as an authorized
redirect URI. For production, add the production origin and
`https://<your-production-domain>/api/auth/callback/google` too.

For GitHub, create an OAuth App and use
`http://localhost:3000/api/auth/callback/github` as its authorization callback
URL. GitHub OAuth Apps accept one callback URL, so create separate local and
production OAuth Apps if both environments need to sign in. Set each app's
client ID and secret in that environment.

On Vercel, configure `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`,
`BETTER_AUTH_GOOGLE_CLIENT_ID`, `BETTER_AUTH_GOOGLE_SECRET`,
`GITHUB_CLIENT_ID`, and `GITHUB_CLIENT_SECRET` in Project Settings →
Environment Variables. Also set `MONGODB_URI`; this project requires MongoDB
on Vercel because its local SQLite database is not persistent there. Set
`BETTER_AUTH_URL` to the production origin, and register the corresponding
production callback URLs with Google and GitHub. Keep OAuth secrets
server-side; do not prefix them with `NEXT_PUBLIC_`.

Better Auth creates or retrieves the user and provider-account records in the
configured database, establishes the session, and sends the user to the
requested in-app destination. Google and GitHub accounts with the same verified
email can be linked only when the existing local account's email is verified.
Other email/account conflicts are rejected rather than linked automatically;
the user can still sign in with the original provider or email/password method.
